Under the hood

There's a full engine under this.

Forecasting model, optimization math, ROI logic, target buildings — what's actually running the decision.

Data pipeline: sensors and meters stream readings continuously, not in nightly batches, so the system is always working off the last few minutes, not yesterday's report. A lightweight stream layer keeps a rolling window of live data, which is what lets the forecast update every few minutes and the optimizer react the moment occupancy or price changes — instead of waiting for a batch job to run.

Forecast: a lightweight model (regression, random forest, or a moving-average baseline for the MVP) predicts each load's demand for the next 30–60 minutes from occupancy, temperature and time of day — simple enough to explain to a judge or a facility manager.

Optimizer: every flexible load carries a power draw, duration, earliest start, latest start and comfort limit. The optimizer only moves what's marked flexible, only inside its deadline, and never touches anything marked critical.

In practice: a manager opens the dashboard and sees live demand, not a static chart. When the forecast crosses the target, the app flags it, proposes a shift (which load, how long, how much it saves) and waits for a tap to confirm — or runs it automatically if auto-optimize is on. Every action is logged, so the next day's forecast is a little more accurate than the last.

ROI: savings are calculated from the building's own demo data and labelled as an estimate, next to a deployment cost and a payback period — not a promised percentage.

First customers: colleges, mid-size offices and hotels, where electricity is a real line item and the retrofit pays for itself in months, not years.
